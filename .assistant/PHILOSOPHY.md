# PHILOSOPHY — Правила работы над проектом ONDA

## 1. Перед изменениями
- Всегда сначала прочитай `replit.md` (текущее состояние проекта).
- Если задача про фронтенд — смотри `.assistant/MODULE_FRONTEND.md`.
- Если задача про iOS/Android — смотри `.assistant/MODULE_NATIVE.md`.
- Если задача про Supabase — смотри `.assistant/MODULE_SUPABASE.md`.

## 2. Где менять код
- По умолчанию правь существующие файлы в `src/`.
- **НЕ создавай** файлы с суффиксами `_fix`, `_final`, `_corrected`, `_new`.
- Если нужен новый файл — сначала объясни, зачем он и в какой модуль относится.
- Главный компонент приложения: `src/onda-level1-demo_27.tsx`.

## 3. Размер изменений
- Один запрос — один небольшой логичный шаг (одна фича, один фикс).
- Не переписывай сразу всю архитектуру без явной команды.
- Для крупных изменений — составь план и согласуй с пользователем.

## 4. После изменений
- Кратко опиши, что изменилось.
- Укажи, в каких файлах сделаны изменения.
- Дай инструкцию, как проверить изменения (пересборка iOS, рестарт и т.д.).

## 5. Тесты и качество
- Если меняется логика — проверь работу через консоль браузера.
- Следи за согласованностью типов, импортов и маршрутов.
- Тесты находятся в `src/tests/`.

## 6. Работа с документацией
- Не меняй `.assistant/*` без явной просьбы.
- Если заметил несоответствие между кодом и документацией — укажи на это.
- Обновляй `replit.md` при значительных изменениях архитектуры.

## 7. Особенности проекта ONDA
- Пользователь работает на MacinCloud, не может подключить iPhone к Mac.
- Деплой iOS через GitHub Actions + Fastlane → TestFlight.
- Все сообщения и UI на русском языке.
- Используется Supabase (Auth, Database, Storage, Edge Functions).
- Нативные фичи через Capacitor (iOS) и WebView bridge (Android).
