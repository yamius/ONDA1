# 🔐 Unified Permissions Solution

## 🎯 Суть решения

**Запрашиваем ВСЕ разрешения ОДИН РАЗ при первом запуске!**

```
Пользователь открывает приложение
  ↓
Видит баннер "Настройте разрешения" ⚠️
  ↓
Клик "Настроить сейчас"
  ↓
Модальное окно с объяснением ЗАЧЕМ нужны разрешения
  ↓
Клик "Предоставить все разрешения"
  ↓
4 системных диалога (последовательно)
  ↓
Баннер исчезает навсегда ✅
  ↓
При практике - всё работает без диалогов!
```

## 📁 Реализация

### Frontend (React/TypeScript)

**Файлы:**

1. `src/services/PermissionsService.ts` - Сервис для работы с разрешениями
2. `src/hooks/usePermissions.ts` - React Hook для управления разрешениями
3. `src/components/PermissionWarningBanner.tsx` - Баннер с предупреждением
4. `src/components/PermissionSetupModal.tsx` - Модальное окно настройки
5. `src/onda-level1-demo_27.tsx` - Интеграция в главный экран

**Логика:**

```typescript
// 1. Хук проверяет разрешения при загрузке
const permissions = usePermissions();

// 2. Если нет разрешений - показываем баннер
{permissions.needsSetup && (
  <PermissionWarningBanner onSetupClick={() => setShowModal(true)} />
)}

// 3. Модалка последовательно запрашивает разрешения
await permissions.requestAllPermissions((permission, granted) => {
  // Обновляем UI в реальном времени
});
```

**Запрашиваемые разрешения:**

1. **HealthKit (read)** - Пульс, Сон, Активность
2. **HealthKit (write)** - Тренировки, Медитации  
3. **Микрофон** - Голосовые практики, Эмоциональная сверка
4. **Уведомления** - Напоминания о практиках

---

### Backend (iOS/watchOS)

**Упрощение кода часов:**

```swift
// ❌ УДАЛЕНО (было лишнее):
saveHeartRateToHealthKit(roundedValue)

// ✅ HKWorkoutSession АВТОМАТИЧЕСКИ сохраняет HR!

```

**Разрешения на часах запрашиваются автоматически:**

```swift
// При запуске HKWorkoutSession watchOS показывает диалоги:
let session = try HKWorkoutSession(...)
try session.startActivity(with: Date())

// → Системный диалог "Allow Health Data Access"
// → Системный диалог "Allow Health Data Write"
```

## ✅ Преимущества

### 1. Проактивный подход
- ✅ Запрашиваем разрешения ДО начала использования
- ✅ Пользователь понимает ЗАЧЕМ нужны разрешения
- ✅ Нет неожиданных диалогов во время практики

### 2. Единый UI
- ✅ Все разрешения в одном месте
- ✅ Красивое модальное окно с объяснениями
- ✅ Прогресс в реальном времени (галочки)

### 3. Минимум диалогов на часах
- ✅ Только 2 системных диалога (минимум от Apple)
- ✅ Появляются ОДИН раз при первом запуске
- ✅ Нельзя убрать (требование безопасности watchOS)

### 4. Graceful degradation
- ✅ Если пользователь отказал - можно настроить позже
- ✅ Кнопка "Пропустить" всегда доступна
- ✅ Баннер остаётся пока не будут даны все разрешения

## 🔄 UX Flow

### Сценарий 1: Первый запуск (идеальный)

```
1. Открыли приложение → Видим баннер ⚠️
2. Клик "Настроить сейчас" → Модалка
3. Клик "Предоставить все" → 4 системных диалога
4. Все разрешили → Модалка закрывается, баннер исчезает ✅
5. Запустили практику → Всё работает! ✅
```

### Сценарий 2: Отказ от разрешений

```
1. Открыли приложение → Видим баннер ⚠️
2. Клик "Пропустить" → Баннер остался
3. Запустили практику → Частичный функционал:
   - Нет пульса → "--" вместо BPM
   - Нет микрофона → Эмоциональная сверка недоступна
4. Вернулись на главный → Баннер ⚠️
5. Решили настроить → Повторяем запрос
```

### Сценарий 3: Частичные разрешения

```
1. Пользователь разрешил HealthKit, но запретил микрофон
2. Модалка обновляет статус в реальном времени:
   ❤️ Пульс [✓]
   🎤 Микрофон [  ] ← нет галочки
3. Баннер остаётся (не все разрешения)
4. Можно настроить позже в меню "Подключения"
```

## 📝 Примечания

### Почему убрали `saveHeartRateToHealthKit`?

**HKWorkoutSession автоматически сохраняет HR samples в HealthKit!**

Мы делали лишнюю работу:
```swift
// ❌ Было (лишнее):
builder.statistics → получаем HR → вручную сохраняем

// ✅ Стало (правильно):
builder.statistics → получаем HR → отправляем на iPhone
HKWorkoutSession → автоматически сохраняет в HealthKit
```

### Почему минимум 2 диалога на часах?

**Требование безопасности watchOS.**

Apple не позволяет third-party приложениям:
- Обходить системные диалоги разрешений
- Работать в фоне без разрешения
- Изменять дизайн системных диалогов

Это **минимум**, который можно достичь! ✅
